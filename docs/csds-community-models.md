# CSDS Community Currency Models

Models that classify **CSDS** (Community Services Data Set) care contacts into the NHSE community currencies and attach indicative prices. Source logic: NHSE "Community Currency SQL grouping v1.1" (April 2026, for 25/26 data), reimplemented as layered dbt models with the mappings in seeds; prices from the community contact section of the NHSE 26/27 price schedule.

## The currency framework in one minute

Community currency codes are `CA…Z` (adult) or `CC…Z` (children and young people), grouped by service area — e.g. `CAL03Z` = Adult / Long-term condition management / Diabetes; `CCS03Z` = CYP / Short-term intervention / Audiology. Unlike the MH currencies there is no setting suffix logic: the team type (and for a few teams, the referral reason) decides the code outright.

Assignment rules, exactly as in the NHSE script:

1. **Age category** from age at referral: 0–17 → CYP, 18+ → Adult, missing or negative → Adult.
2. **Team type** (CYP102) maps to a currency per age category via the team-types seed.
3. **Reason-split teams** — Adult District Nursing (12) and Integrated MDT (45); CYP additionally Community Paediatrics (06) and Children's Community Nursing (38) — take their currency from the **primary reason for referral** instead (e.g. an end-of-life reason routes District Nursing to `CAE08Z`), falling back to the team's own "Other …" code when the reason is missing or unmatched.
4. Unmapped or missing team types fall to `CAO99Z` / `CCO99Z` (Other Community Services).

`currency_source` on every row records which route resolved it (team_type / reason_split / team_fallback / unmapped_team).

## Seeds

| Seed | Maps |
|---|---|
| `nhse_community_currency_team_types_2526` | (age category, team type) → currency; reason-split teams flagged with their fallback code |
| `nhse_community_currency_referral_reasons_2526` | (age category, team type, referral reason) → currency for the split teams |
| `nhse_currency_prices_2627` | Currency code → 26/27 indicative price (community section) |

Both mapping seeds were generated by script from the NHSE source SQL, not hand-transcribed.

## Staging — `models/staging/commissioning/csds/`

All CSDS staging deduplicates via `deduplicate_csds`: latest record per business key within active submissions (CSDS is a monthly resubmission feed like MHSDS — never count raw rows).

- `stg_csds_cyp101referral` — one row per referral (age at referral, primary reason, commissioner).
- `stg_csds_cyp201carecontact` — one row per (referral, contact): date, attendance, provider, commissioner.
- `stg_csds_servicetype` — one team type per referral (latest submitted).
- `stg_csds_mpi` — one row per person: latest residence (LSOA21, local authority, sub-ICB), gender, death date, ethnic group.
- `stg_csds_gp_registration` — dated GP practice registrations per person (start/end), for as-at attribution.
- `stg_csds_bridging` — person → pseudonymised patient id.

## Classification — `int_csds_contact_currency`

One row per (referral, contact) — provider-local contact ids are reused across referrals, so the contact id alone is not unique. Applies the four assignment rules above, then attaches:

- **Commissioner**: contact-level DMIC-derived ICB and sub-ICB, falling back to the referral's (~99% coverage).
- **Practice**: the GP registration whose dates bracket the contact date (~92% of contacts), else the person's latest registration — `practice_attribution` says which. Practice name, PCN and registered borough via the WNL PCN membership lookup.
- **Residence**: LSOA21 and borough (all-England lookup) plus sub-ICB of residence from the latest MPI record (~94% coverage).

## Pricing — `fct_csds_currency_contacts`

One row per (referral, contact). Unit prices resolve through `int_nhse_currency_price_resolution` (all community codes price exactly), are rebased from the 26/27 price base to the contact's fiscal year with the GDP deflator, and adjusted by the provider Market Forces Factor. Attended contacts (status 5, 6, or missing) are costed; DNAs and cancellations are kept with `proxy_cost = 0`.

## Caveats analysts should know

- **Null attendance is the largest category (~54% of contacts) and it is costed.** This follows the NHSE v1.1 rule (nulls treated as attended to avoid deleting activity for completeness reasons) and it is structural — every provider runs 12–92% null. Any comparison against reporting that counts only explicit 5/6 will differ materially.
- **About a third of contacts are out-of-area**: WNL community providers delivering for other ICBs. The fact does not filter them — cut by `dm_icb_commissioner` (WNL = QMJ/QRV). PCN fields populate for WNL-registered practices only (~90% of WNL-commissioned contacts, ~1% of out-of-area).
- **Adults appear on children's team types and vice versa** — mostly genuinely (mothers receiving antenatal/safeguarding care under children's community services, average age 31) plus some team-type miscoding in the elderly. The NHSE age-only rule is applied deliberately; these land in the Other Community Services codes.
- **These are proxy costs** — national indicative prices on activity, for comparative and distributional analysis, not contract reconciliation.
- Residence and practice context reflect the latest/at-contact submitted state; historical residence moves are not tracked (known refinement).
